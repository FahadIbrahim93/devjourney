## 7-DAY CRASH COURSE PLAN

### Day 1: Next.js Foundations

```
Goal: Build a simple Next.js app with routing + SSR

Resources:
- nextjs.org/learn (free, official)
- Build: A simple blog or portfolio site in Next.js

Deliverable: Deploy a Next.js app to Vercel
Time: 3-4 hours
```

### Day 2: Next.js Advanced

```
Goal: API routes, data fetching, auth

Resources:
- Next.js docs on API routes
- NextAuth.js tutorial
- Server Components vs Client Components

Deliverable: Add authentication + API routes to Day 1's app
Time: 3-4 hours
```

### Day 3: Testing (Jest + Vitest)

```
Goal: Write unit tests for React components

Resources:
- Vitest docs (vitest.dev)
- React Testing Library docs
- Tutorial: "Testing React Apps with Vitest"

Deliverable: Write tests for 3 components from BugSmasher
Time: 2-3 hours
```

### Day 4: Docker Basics

```
Goal: Understand containers, Dockerfile, docker-compose

Resources:
- Docker's "Getting Started" tutorial
- docker-curriculum.com

Focus: Concepts, not depth
Time: 1-2 hours
```

### Day 5: System Design Basics

```
Goal: Understand 5 common system design patterns

Topics to learn:
1. URL shortener (hash + redirect)
2. Chat system (websockets)
3. Rate limiter (token bucket)
4. Database scaling (sharding, replication)
5. Caching strategies (CDN, Redis)

Resources:
- "System Design Interview" by Alex Xu
- YouTube: system design interview channel

Deliverable: Be able to whiteboard 2 patterns
Time: 3-4 hours
```

### Day 6: Portfolio Updates + Applications

```
Goal: Update GitHub + portfolio with new skills

Actions:
1. Add Next.js project to GitHub
2. Update portfolio with testing badge
3. Apply to 10 jobs
4. Update LinkedIn with any new skills

Time: 3-4 hours
```

### Day 7: Mock Interview + Review

```
Goal: Practice interview skills

Actions:
1. Record yourself answering 5 common interview questions
2. Review recording for improvement areas
3. Apply to 10 more jobs
4. Plan next week

Time: 2-3 hours
```

## THE ONE-PAGE CHEAT SHEET (Print This)

```
REACT INTERVIEW CHEAT SHEET
═══════════════════════════════
• useState/useEffect/useRef/useContext/useReducer
• Virtual DOM: JSX → React elements → Fiber → DOM
• Reconciliation: key props, same-element optimization
• useCallback/useMemo: when and why
• Custom hooks: extract logic, reuse state
• Error boundaries: componentDidCatch, fallback UI

TYPESCRIPT CHEAT SHEET
═══════════════════════════════
• type vs interface
• Generics: <T extends ...>
• Utility types: Partial, Pick, Omit, Record
• Union vs Intersection types
• Type narrowing: typeof, instanceof, discriminated unions

SYSTEM DESIGN CHEAT SHEET
═══════════════════════════════
1. Understand requirements (functional vs non-functional)
2. Estimate scale (DAU, QPS, storage)
3. Design data model
4. High-level architecture (client → LB → API → DB → cache)
5. Deep dive on key components
6. Trade-offs (consistency vs availability)
```

## APPLICATIONS WHILE LEARNING

**Don't wait until you've learned everything.**
Apply WHILE you learn.

```
Skill Level → Apply?

React + TS only → Apply to React/TS roles (many exist)
Learning Next.js → Apply to "React" roles, learn Next.js on the job
No testing yet → Apply anyway, mention "learning testing"
```

**Companies hire for potential + attitude, not complete skill matches.**
Apply if you meet 60%+ of requirements. Let THEM decide if you're a fit.

*You don't need to know everything. You need to know enough to pass the interview and learn the rest on the job.* 🚀
