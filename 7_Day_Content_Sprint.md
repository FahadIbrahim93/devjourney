```
- Auth flow (3 different OAuth providers)
- State management for game progression
- Cloud sync conflicts when offline
- Leaderboard race conditions

- Start with Zustand earlier
- Use Supabase RLS from day 1
- Write tests before features, not after
```

### Evening (6:00 PM ET)

#### LINKEDIN — Article/Post
```
BugSmasher: A case study in shipping fast

Last month, I built and deployed a full-stack arcade game in 2 weeks.

Tech stack: React 19, TypeScript, Supabase, Vite.

Here's what I learned:

1. CHOOSE YOUR STACK WISELY
I picked tools I already knew. No "shiny new framework" on day 1.
React 19 + TypeScript = type safety + performance.
Supabase = auth + database + real-time = one backend.

2. BREAK THE MONOLITH EARLY
I started with one big component. Day 3 I refactored into 12 smaller components.
Should have done this from the start.

3. TESTS ARE NOT OPTIONAL
I wrote 9 passing Vitest tests. They caught 3 bugs before production.
Testing isn't slowing you down. It's saving you from 3am fire drills.

4. SHIP IMPERFECT
Version 1 didn't have:
- Sound effects
- Mobile optimization
- All 16 achievements

But it shipped. And that matters more than perfect.

The goal is not to build something that looks good.
The goal is to build something that works — and keeps working.

What's the fastest you've shipped a production app?
```
